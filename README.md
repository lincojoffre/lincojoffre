## About

I am a Brazilian developer and entrepreneur working at the intersection of **software engineering, AI, automation, data and business operations**.

My path started with programming and Digital Game Development — C#, C++, Unity and interactive systems — and gradually moved toward backend architecture, APIs, workflow automation, internal tools, cloud infrastructure and AI-enabled products.

```text

```

I currently study **Analysis and Systems Development** while building practical systems through **Joffre Negócios Digitais** and independent technical projects.

## Engineering approach

I prefer systems that are understandable before they are impressive.

<table>
<tr>
<td valign="top"><strong>01 · Understand</strong><br><br>Map the real process, actors, constraints, data and failure modes before choosing technology.</td>
<td valign="top"><strong>02 · Contract</strong><br><br>Turn rules, schemas, permissions and invariants into explicit contracts instead of hidden assumptions.</td>
<td valign="top"><strong>03 · Build</strong><br><br>Implement incrementally with clear boundaries, tests, environment separation and observability.</td>
<td valign="top"><strong>04 · Learn</strong><br><br>Use operational evidence to improve the product, workflow and decision model continuously.</td>
</tr>
</table>

### Principles I repeatedly use

```text
Understand before automating.
Human-in-the-loop where ambiguity matters.
AI supports the system; it does not become the system.
Facts and decisions should be distinguishable.
Important decisions should be observable and explainable.
Security and data governance start in the architecture.
Credentials never belong in source code, prompts or logs.
Private operational data should stay out of public repositories.
Documentation should preserve reasoning, not only describe files.
```
